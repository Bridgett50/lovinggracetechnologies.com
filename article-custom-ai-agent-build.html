What a custom AI agent build includes

A custom agent is built around one workflow, your records, and approval gates. What the build includes, start to finish.

A custom AI agent is not a chatbot with your logo on it. It is a defined piece of work, built around one workflow, your records, and the approval gates that keep you in charge. Here is what a build includes, in the order the work runs. The steps below state the build standard. The completed run that shows the standard working is the Second Seat demonstration, named as a demonstration wherever it appears.

  1. Brief. The build starts with the work itself: what repeats, what it costs today, and what a good result looks like. The build is scoped from actual facts, not from a template.
  2. Verify. The build standard requires checking the records the agent will rely on and testing the controls for what they can and cannot catch. A claim the agent makes should trace back to a source. If the source is missing, the build says so before anything is automated.
  3. Map. The workflow is mapped as it actually runs today: the steps, the handoffs, the decisions, and the records. If the workflow cannot be described back accurately, the build will not fit it.
  4. Model. The agent is designed as an orchestration: intake takes the request in one shape, triage sorts it, specialist reasoning does the work, and one command center holds the whole picture. Drafting and checking are separate jobs, and approval belongs to a person.
  5. Resource. The build standard calls for selecting tools and models that fit the work, including evaluating self-hosted options where control matters. The build states plainly where files live, who controls the infrastructure, and what happens to data and systems if the engagement ends.
  6. Ask. Before anything the agent drafts is sent, paid, or changed, a person approves it with the evidence in front of them. The Second Seat demonstration ran this step end to end: a separate checker reviewed the payment draft and the owner approved the test payment before execution. In the PayPal sandbox demonstration, a fake bank-change request was blocked, and a clean $480 payment was approved and captured as completed. That was a demonstration, not a client payment, and it is described here as one.
  7. Command. The owner keeps the final say. The agent handles the routine. People handle the exceptions, the judgment calls, and the final approval. The build should make those moments easy to find and easy to act on.

That is the build standard: defined work, kept evidence, readable reasons, and a person approving what matters. The Second Seat demonstration illustrates the intended approval gate in one sandbox workflow. A build applies the same standard to yours, scoped from your facts.

Call to action: Describe the work that repeats in your business. We will tell you plainly whether an agent fits it, and what the build would include.
