Claude linked billing: the key never changes hands.

Anthropic put linked billing into beta on Nov 17, 2026. A customer links their Claude organization to an app once, sets a spend limit, and pays without sharing an API key. The requests still run in the platform's organization.

On Nov 17, 2026, Anthropic put linked billing into beta on the Claude Platform. The change is small and it matters. A customer can now pay for Claude API usage inside a third-party app without handing that app an API key.

The old pattern was the problem. Paying for Claude inside a coding agent or workflow tool usually meant sharing an API key. Anthropic's own article says the key works like a password: anyone who has it can make requests billed to the customer, so the platform has to keep it safe. That meant customer keys stored on someone else's servers, encrypted and rotated by someone else, with the spend landing on the customer's bill either way.

Linked billing replaces the key with a link. The customer connects their Claude Platform organization to the app once, through an approval page Anthropic hosts. The app then chooses on each request whether the platform or the customer pays, by setting a billing_policy field. The customer approves each linked platform, sets a monthly spend limit for it, and can unlink it at any time from the Claude Console. If a request marked for the customer cannot be billed to them, the API refuses it instead of quietly charging the platform. The platform can see each linked customer's request count, token usage, and models used in Console, or through the Usage and Cost Analytics API in beta.

The customer keeps their existing billing relationship with Anthropic. They can draw down from an existing commitment or pay as they go. Anthropic lists 19 platforms supporting linked billing at launch: Asana, ClickHouse, Factory, Gumloop, Harness, Higgsfield AI, Kilo Code, Linear, Major, Mintlify, Omni, OpenArt, Niteshift, Railway, Ramp, Runlayer, Tessera, Tines, and Warp.

The part to read twice is where the requests run. They run in the platform's organization, not the customer's. Anthropic's article states it plainly: settings in the customer's organization, such as IP allowlists, encryption keys, and data retention, do not apply. The documentation goes further. The customer's own data arrangements do not apply to these requests, including zero data retention, a business associate agreement, and customer-managed encryption keys. The docs say not to link customers who need HIPAA, FERPA, or CMEK coverage for this usage. Only the billing moves to the customer. The execution, the rate limits, the model access, the service tier, and the data handling stay with the platform.

Eligibility is narrow for now. A customer can be billed this way only if their Claude Platform organization pays Anthropic directly, by prepaid credits or invoiced billing. Organizations billed through a cloud marketplace, AWS, Google Cloud, or Azure, cannot be billed through the integration, and neither can organizations that hold only a Claude subscription plan. Requests for those organizations are refused with a 403. The monthly API credits that come with Claude Max, Ultra, and Team plans cannot pay for these requests either. Anthropic also excludes credits from partner, venture-capital, and startup programs. The supported endpoints are /v1/messages and /v1/chat/completions, although customer-billed /v1/messages requests cannot use billable code-execution features and return a 400 error if they do. Message Batches does not support billing the customer yet. Anthropic warns the beta can change: endpoints, parameters, and behavior can change during the beta, and it might not be suitable for production use.

Five checks worth keeping before linking an organization to any platform

  1. Confirm who pays on each request. The platform decides per request. Ask which requests the customer pays for and which the platform covers, and get the answer in writing before the first link.
  2. Set the spend limit before the first request, not after the first bill. The customer sets a monthly limit per platform in Console. A limit set late is a bill already sent.
  3. Read the execution split, not just the billing split. The customer's IP allowlists, encryption keys, and retention terms do not travel with the request. If any of those is a requirement, the customer should not link.
  4. Check eligibility before promising it. Marketplace-billed organizations and plan-only organizations are refused. Confirm the organization pays Anthropic directly before telling a customer this is available.
  5. Know what the unlink does and does not do. Unlinking stops future billing. It does not pull back requests already made or data already handled under the platform's terms.

What to watch

whether Anthropic extends linked billing to Message Batches and Managed Agents, whether the HIPAA, FERPA, and CMEK exclusion lifts, and whether other model providers copy the pattern, so a customer can pay inside any tool without ever handing over a key.
